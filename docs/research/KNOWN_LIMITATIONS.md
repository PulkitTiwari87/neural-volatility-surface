# Known Limitations

**Status:** IN_PROGRESS — living document; currently lists limitations known **before any implementation** (design-time). Items must be updated with measured evidence as work proceeds. · **Source:** MP header, §3, §6, §8–§10, §14, §25 · **Surfaced in:** Methodology page (UI-011), forecast views, release notes (AC-11)

| L-18 | All feasibility results so far are **synthetic**: they verify pipeline logic and detection ability, not real-market behaviour, quote noise, or provider data quality; the v1 detection procedure was run on only 9–10 seeds per world (an exploratory post-hoc study later used 190–200 seeds per world, [PHASE0_AUDIT](PHASE0_AUDIT.md) §5). | Phase 0 spike ([results](PHASE0_SYNTHETIC_RESULTS.md) §9) | Over-reading synthetic success | Every result labelled SYNTHETIC; real-sample evidence required for the Phase 0 gate | Active |
| L-19 | The block-5 percentile bootstrap under-covers (coverage 85.8–93.3 % vs 95 % nominal in the audit's synthetic test, worst with serial dependence), so "improvement detected" is a liberal screening rule, not a calibrated 2.5 % test; the random-walk false-positive rate is 1.6 % among valid synthetic worlds but up to 6.5 % if the 5 % of rejected (invalid) worlds were all detections. | [PHASE0_AUDIT](PHASE0_AUDIT.md) §5; [decision.md](../../decision.md) PA-1, PA-4 | Over-reading "detected"; understated false-positive rate | Quote conditional and worst-case rates together; no inferential claim (PA-1 closed NO-GO 2026-10-13, see L-22) | Active |
| L-20 | The `chainpipe` chain→surface→baseline path (2026-10-13) is exercised only on clean **synthetic** chains: no real quote noise, stale or crossed quotes at scale, missing per-contract timestamps, AM/PM (SPX/SPXW) settlement mix, or provider field quirks. Its tests prove the code does what it states, not that the thresholds, day-count, forward-from-parity inference or ±25 % forward plausibility check hold on real chains. | [IMPLEMENTATION_MATRIX](../engineering/IMPLEMENTATION_MATRIX.md) items 3, 5, 6 | Over-reading passing tests as data readiness | Spike labels and `SYNTHETIC - not market data` on every output; real-sample experiment before any adoption | Active |
| L-21 | With strikes on a K grid and surface nodes on forward log-moneyness, `observed` surface cells almost never occur (the 12-day synthetic series produced none); surface-cell baselines are scored on `interpolated` cells and are reported by target status, not as observed-market skill. The no-arbitrage diagnostics are necessary-condition flags only. | Q-25; [IMPLEMENTATION_MATRIX](../engineering/IMPLEMENTATION_MATRIX.md) items 6, 10, 11 | Interpolation structure mistaken for market structure; false assurance of arbitrage-freedom | Per-status reporting in `chainpipe-eval-1`; contract-level task uses actual quote IVs; DEC-006 / Q-25 experiment on a real sample | Active |
| L-22 | No statistical-inference method for model-versus-baseline comparisons has been validated. The A2b-v1 gate found no admissible interval method (`NO_METHOD_ADMISSIBLE`); the A2d diagnostic identified mechanisms of the size distortion but no validated remedy; the search was closed by the owner on 2026-10-13 (PA-1 CLOSED — NO-GO). | [PHASE0_CLOSURE_RECORD](PHASE0_CLOSURE_RECORD.md) §7; [decision.md](../../decision.md) PA-1 | Statistical significance, p-value-style, size or coverage claims would be unsupported and likely liberal | Report descriptive paired loss differences by region and period with sample counts and explicit limitations; treat `improvement_detected` as a labelled screening statistic only; a future method needs a new owner-approved protocol and independent validation | Active |
| L-23 | **E-1 hosted-data lab.** SPY options are American-style but IV is computed with European Black-76 on **OTM mid** prices only; the forward and discount factor are *implied* per expiry from put-call parity (also approximate for American options); no rate/dividend series; closing-snapshot mids, not executable prices; no per-contract timestamps. Systematic bias in IV level is possible, especially for long maturities and around ex-dividend dates. | [HOSTED_DATASET_ASSESSMENT](../data/HOSTED_DATASET_ASSESSMENT.md) §4; `backend/src/volatility_lab/validation/quotes.py` | IV level/term-structure bias; early-exercise premium ignored | OTM-only selection; parity-implied F and DF; vendor IV used only as a unit-agnostic sanity ratio; no claim of market-consistent IV | Active |
| L-24 | **E-1 data licence and scope.** The hosted dataset is one underlying (SPY), one vendor (OptionsDX, via a Kaggle uploader's MIT label), one daily snapshot. The upstream licence is **unverified**; results cannot be generalised to other underlyings, vendors, intraday data or periods; backtest only, never "live". | [HOSTED_DATASET_ASSESSMENT](../data/HOSTED_DATASET_ASSESSMENT.md) §3 | Over-generalisation; redistribution/publication exposure | Private research use; no data redistribution; DEC-002 stays open for a licensed source | Active |
| L-25 | **E-1 evaluation scope.** Neural models were run with fixed a-priori hyper-parameters (no search), 3 seeds per (fold, model), 1-day horizon, 54 cells; comparisons are descriptive (no p-values or intervals, see L-22); the primary metric uses only OBSERVED target cells, so it under-represents sparse wings and long maturities; regime splits use realised-vol terciles from training data only. | `docs/research/E1_RESULTS.md` | Reading a descriptive ranking as proof of skill | Report per-year, per-region metrics and sample counts; require stability across test years before saying a model "helps" | Active |
| L-27 | **Phase 2 comparison is synthetic and generator-dependent.** Interpolation and quote-filter rankings in [PHASE2_SURFACE_COMPARISON](PHASE2_SURFACE_COMPARISON.md) come from a smooth quadratic-in-k, linear-in-IV-in-T generator with cent-rounding as the only noise; known-answer tests show the T-direction ranking flips with the generating truth, and every method difference (≤ 0.15 vol points) is below real quote noise (median vendor-vs-own IV difference 0.31 vol points). | `surfaces/compare_methods.py`; `tests/scientific/test_interpolation_comparison.py` | Choosing DEC-006 from synthetic rankings | DEC-006 stays open; harness to be rerun unchanged on a permitted real sample under a pre-registered rule | Active |
| L-28 | **IV recovery tolerances were written after E-1 ran on real data.** Phase 2 A1 requires tolerances set before real-data runs; E-1 (2026-10-13) predates `tests/scientific/test_iv_recovery.py` (2026-10-16). Recovery is verified on synthetic prices only, and deep in-the-money quotes (vega < 1e-4·F) do not identify volatility (184 of 886 solvable grid cells, error up to 1.4e-3), which is why only OTM quotes are inverted. No per-quote solver status/iterations are stored (GR-QNT-03 partial). | [PHASE2_SURFACE_COMPARISON](PHASE2_SURFACE_COMPARISON.md) §2 | Over-stating Phase 2 A1/A2 | Ordering caveat recorded; per-quote diagnostics listed as next core task | Active |
| L-26 | **E-2 label comparison.** The nearest-expiry (roughly constant-maturity) and same-expiry (roll-down) labels measure different quantities, have different eligible samples (36,793 vs 35,838 cells; 28,525 common) and give different model rankings; the fixed-expiry label censors 4.9 % of anchored cells and is not a single-contract fixed-strike label; neither is established as the right forecasting target, and the one-day maturity decay is not adjusted for. | [E2_FIXED_EXPIRY_RESULTS](E2_FIXED_EXPIRY_RESULTS.md) | Reading a ranking under one label as skill; mistaking a label artefact for forecastability | Report both labels and the common sample; require agreement across labels and years before saying a model helps; test a maturity-adjusted label and expiry features next | Active |
| L-29 | **H1–H6 figures exist only as transcriptions.** The H-series notebooks in the repository carry no cell outputs and no run directory was saved outside the Colab/Kaggle runtimes; the numbers in the review (some read from screenshots by a browser agent) cannot be re-hashed or re-computed from stored artifacts, and the full config hash is unreadable beyond the shared prefix `28b90c2a`. Each was one run on hosted data of unverified licence. The owner declined independent verification on 2026-10-20 ("no need to verify the results of H1 - H6"); this is recorded, not a validation. | [PHASE4_NEURAL_EVIDENCE_REVIEW](PHASE4_NEURAL_EVIDENCE_REVIEW.md) §3.8–3.11 | Treating transcribed single-run numbers as reproduced evidence | Quote them only as "recorded in the review"; any re-run needs an owner-run GPU session and a saved manifest | Active |
| L-30 | **Calendar features can encode the label's deterministic roll-down.** The fixed-expiry label contains the mechanical roll-down of a fixed contract; days-to-expiry features (H3–H6) describe exactly that, so a model positive only under the fixed-expiry label (the GRU in H5/H6, PCA-ridge in H3/H4) may be learning the calendar, not market dynamics. | [PHASE4_NEURAL_EVIDENCE_REVIEW](PHASE4_NEURAL_EVIDENCE_REVIEW.md) §3.10 | Reading a one-label result as forecasting skill | Require agreement under both labels; test a maturity-adjusted label | Active |
| L-31 | **Phase 1/2 hardening is synthetic-tested only.** Strict ISO date parsing, duplicate-row handling and the new solver-range statuses (2026-10-20) were tested on generated rows; their effect on the hosted SPY file was not measured (the file is not available here and per-reason E-1 ledger counts were not saved), so the E-1/E-2/H-series ledgers may differ from a re-ingest under the new code. No exchange-holiday or early-close calendar exists (needs DEC-005). | `backend/tests/unit/test_ingestion_robustness.py`, `tests/scientific/test_iv_recovery.py` | Assuming the executed experiments used the hardened ingestion | Re-ingest by the owner on the hosted file and compare ledgers before relying on the new reasons | Active |
| L-32 | **Leakage audit scope.** The truncation-invariance audit now covers the calendar and mean-reversion feature variants under both labels (2026-10-20, `test_feature_leakage_variants`), but it checks the produced feature blocks as a whole, not each `FEATURE_CATALOG` entry; most catalog entries are still PLANNED. It cannot detect leakage that is present in the stored data itself (for example a vendor field computed with later information). | `backend/tests/unit/test_feature_leakage_variants.py` | Treating a passing audit as proof that the data is leak-free | Keep the audit per feature as features are added; review vendor fields before use | Active |
| L-33 | **Viewer wording.** The static viewer labels data read from a stored run "Live from run"; GR-DATA-07 reserves "live" for real-time licensed data, so the label can be read as live market data. The UI workstream owns `frontend/`; not changed by the core session. UA-01…UA-14 and the accessibility audit have not been run. | `frontend/index.html` | A reader taking stored or synthetic runs for live data | Rename the label (for example "From run files") and run the UA journeys | Active |

| L-34 | **Panel hash and manifest are environment-sensitive across Windows and Linux, not across library versions (AP-004 Patch 1 closed, D-1).** `build_surface_panel` leaves `n_quotes` and `tenor_days` at NumPy's default integer: int32 in a panel stored on the owner's Windows PC (NumPy 1.x; observed `<i4`), int64 on Linux with both NumPy 1.26.2 and 2.1.3 (measured in Colab, 2026-10-21). `panel_sha256` hashes `dtype.str`, and `ingest` byte-compares the manifest (including `reprice_err_max`), so re-ingesting a store written on another machine or version may raise `OverwriteError`. `verify_dataset` is unaffected (it hashes the stored arrays). Measured 2026-10-21 (Colab, one Linux host): numpy 1.26.2 / pandas 2.1.3 / scipy 1.14.1 and numpy 2.1.3 / pandas 2.2.3 / scipy 1.16.3 give byte-identical panels and Phase 2 JSON, so exact hashes are stable across those library versions; against the PC-written panel 0.2–1.2 % of float values differ by at most 1.7e-14 (cause unexplained: Windows, CPU or the code changes since the store was written), so the hash is not a PC-to-Linux identity, and an explicit int64 would not change that. Colab CPU models vary between sessions and were not tested. The owner closed Patch 1 on 2026-10-21 as not needed under Colab-only execution and kept the strict byte-compare. | `surfaces/grid.py`, `storage/raw_store.py` | Treating "rebuild gives an identical hash" as a cross-machine guarantee | Same-environment rebuild only; regenerate synthetic stores after code changes; execute only in Colab | Active (accepted by the owner; Patch 1 closed) |
| L-35 | **Neural resume cache fails closed but does not repair (AP-004 Patch 4).** `run_neural` refuses to resume unless `run_key.json` matches exactly, so output directories written before 2026-10-21 cannot be resumed (a new `out_dir` is required) and any mismatch is a hard `RunKeyError`. For PCA-factor runs the key records numpy/python/platform strings, **not** the LAPACK/BLAS build, so a different build with the same strings could still yield a different SVD sign on resume. The wiring was verified in Colab only with `train_and_predict` stubbed (no real training), and whether any executed H3–H6 run reused a stale directory cannot be determined from the repository. | `experiments/runner.py` | Assuming resume is safe across machines, or that H3–H6 outputs were never reused | Use a fresh `out_dir` per experiment; do not resume PCA-factor runs on a different machine | Active |
| L-36 | **API edge behaviour (AP-004 Patch 3).** The Host guard refuses any non-loopback `Host` (including `127.0.0.2` and the machine name), a table cell that parses as `nan`/`inf`/overflow is `null` (so a text cell literally `nan` also becomes `null`), the whole CSV is still read before truncation to 5,000 rows, and a negative forecast origin index is still not rejected. The viewer's handling of `null` in a numeric table column was not checked by the core session. `HEAD` now returns 405 with a JSON body (a body on a `HEAD` response is non-standard). Verified with real-socket tests in Colab; a live-server P2 re-run was not repeated. | `api/server.py`, `api/service.py` | A reader seeing `null` and assuming a missing measurement rather than a non-finite value | UI session to render `null` table cells explicitly; keep tables free of text values that parse as numbers | Active |

**Rule:** a limitation is removed only with evidence that it no longer applies; otherwise it remains and may be refined. New limitations discovered in experiments are added with the experiment ID.
